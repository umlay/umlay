# Umlay とは

> **UML, relaid.** — レガシー UML を現代の Node / クラウド / AI 時代に置き直すモデリング基盤。

## 解く問題

既存の UML / ER モデリング手法・ツールには、現代のソフトウェア開発に対して次の制約があります。

| 分類 | 既存の課題 |
| --- | --- |
| 構文 | リレーション名 + 多重度の併記が読みにくい / スペース入り・日本語識別子に弱い |
| 表現力 | ER 図で **ポート矢印 (カラム単位の参照)** が表現できない / シーケンスやコンポーネントの表現が弱い |
| モデル分離 | 1 図 = 1 記述の発想で、同じクラスが図ごとに重複定義される |
| AI 連携 | 図描画に特化した表層 DSL で、意図・契約・不変条件のような**意味論**が載らない |
| 検証 | 「可視性・多重度・型の未指定」「命名の曖昧さ」といった**漏れ**を静的検出できない |
| レビュー | 図はコードと別管理で、Git/PR レビュー文化に乗せづらい |

Umlay はこれらを、**「正本を 1 つだけ持ち、そこから複数の図・コード・IR を派生させる」**という形で解き直します。

## Umlay のアプローチ

```
┌──────────────────────────────────────────────┐
│ 執筆用 DSL   (.uml)     Prisma 風、人間が書く   │
├──────────────────────────────────────────────┤
│ 正規IR       (.uml.json) ツール内部・レビュー用  │
├──────────────────────────────────────────────┤
│ 相互運用     (.uml.yaml) AI / 外部ツール連携用   │
└──────────────────────────────────────────────┘
```

- **単一の正本**: `.uml` (Prisma 風 DSL) を人間が書き、ツールは内部で正規IR (JSON) として扱う
- **複数ビュー**: 1 つのモデルから ER 図、クラス図、シーケンス図、コンポーネント図、WBS、ガントなどを派生
- **意味論を載せる**: 型、多重度、不変条件、意図 (`@intent`) を DSL 上で表現し、AI によるコード生成・レビューに使う
- **Git / PR 親和**: 差分レビュー可能なテキスト形式。指摘・修正を属性単位の注釈として管理

## このリポジトリの位置づけ

本リポジトリ (`umlay-oss`) では以下を公開します。

| コンポーネント | 内容 |
| --- | --- |
| [`packages/spec`](../../packages/spec/) | DSL 文法 + 正規IR の JSON Schema |
| [`packages/examples`](../../packages/examples/) | `.uml` サンプル集 |
| [`skills/`](../../skills/) | 開発者 / AI エージェント向けの skill 定義 |
| [`docs/`](../../docs/) | 本ドキュメント群 |

**実装 (パーサ、Lint、SVG レンダラー、Web エディタ) は別リポジトリで開発中**で、本リポジトリの範囲外です。本リポジトリは「仕様と契約」を公開する場であり、他の実装が `@umlay/spec` に準拠するための一次資料です。

## 関連ツールとの位置関係

| ツール | 強み | Umlay との違い |
| --- | --- | --- |
| **Mermaid** | 普及度 / Web 親和性 | Umlay は意味論 (制約・意図) を載せ、AI / lint 連携を主眼とする |
| **PlantUML** | UML 全図種の表現力 | Umlay は Node / クラウドに特化、文法をコンパクトにし、JVM 非依存 |
| **DBML** | DB 特化で記述しやすい | Umlay は ER に留まらず、クラス / シーケンス / WBS 等まで一モデルから派生 |
| **Structurizr DSL** | モデル → 複数ビューの思想 | Umlay は C4 に限定せず、UML + ER + スケジュール系まで対象 |
| **D2** | レイアウトの美しさ | Umlay は UML 意味論を厚く、lint / AI レビューを仕組み化する |
