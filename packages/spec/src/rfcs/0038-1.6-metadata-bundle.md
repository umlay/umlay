# RFC 0038 — spec 1.6 metadata bundle (RFC 0038–0044)

- Status: **Accepted**
- Shipped in: spec **1.6.0**
- Class: **A — additive**
- Related: RFC 0029 (lint catalog), RFC 0035 (inter-decl directives)

## Motivation

Reviewers, AI agents, and project managers each want metadata that the
spec ≤ 1.5 grammar cannot express. Examples encountered in real review
flows:

- Reviewers ask **who owns this model and which ADR authorised the change**.
- Compliance audits want **PII / GDPR / PCI-DSS tags** at the column or
  model level.
- AI agents (reverse-engineer / write-uml) want **provenance** ("written
  by claude-opus-4-7 from schema.prisma at 2026-04-26") and **confidence**
  scores so review-uml can pick low-confidence inferences first.
- Cross-namespace contracts want **explicit boundaries** — what is
  exposed and what is internal.
- Codegen pipelines want **structured invariant examples** (`@@example`)
  that map to property-based tests.

This RFC bundles seven additive directives + one IR-level field. They
share a common shape (additive, optional, parser-only — lint enforcement
follows in later RFCs) so they can be released together as spec 1.6.

## Surface (8 additions)

| RFC | Construct | Attaches to | Purpose |
| --- | --- | --- | --- |
| 0037 | `IR.specVersion: "1.6.0"` | IR root | Distinguishes spec semantic version from IR schema version |
| 0038-Owner | `@@owner(team:..., reviewer:..., contact:...)` | model | Review routing + escalation |
| 0038-Status | `@@status("in-review", since:..., blockedBy:..., note:...)` | model | Lifecycle state |
| 0038-AdrRef | `@@adrRef("ADR-005")` (repeatable) | model | Authorisation trail |
| 0039-Provenance | `@@provenance(agent:..., from:..., at:..., prompt:...)` | model | "Written by AI X from input Y" |
| 0039-Confidence | `@@confidence(N)` (0..1) | model | Reliability of an AI-authored declaration |
| 0040-Compliance | `@@compliance(tags:[...], residency:..., retention:...)` | namespace / model / attribute | Risk classification |
| 0041-Since | `@@since("X.Y.Z")` | model / attribute | Spec version where this declaration first appeared |
| 0042-Locked | `@@locked(reason:..., by:...)` | model / attribute | "Don't edit without human review" — AI must skip |
| 0043-Example | `@@example(input:{...}, expect:accept|reject, reason:...)` | model | Structured invariant test cases |
| 0044-Boundary | `@@boundary(exposes:[...], hides:[...])` | namespace | Bounded-context contract |

### Grammar additions

- `directiveArgToken` accepts `[ ... ]` array literal (new `nestedSquare`
  rule mirroring `nestedCurly` / `nestedParen`).
- All other directives reuse the existing `@@<ident>(...)` shape.

### Visitor / IR additions

- `IRSchema.specVersion?: string`
- `ModelSchema.owner / status / adrRefs / provenance / confidence / compliance / since / locked / examples`
- `AttributeSchema.compliance / since / locked`
- `NamespaceSchema.boundary / compliance`

All are **additive optional** — pre-1.6 IR consumers see no shape change.

### Object / array argument syntax

```umlay
@@owner(team: "billing-platform", reviewer: "@taro")
@@compliance(tags: ["PII", "GDPR"], residency: "EU")
@@example(input: { total: -1 }, expect: reject, reason: "non-negative invariant")
@@boundary(exposes: ["Order.id", "Order.status"], hides: ["Order.internalSeq"])
```

The visitor's `parseDirectiveObject` walks the flattened token stream
(brace / bracket / paren markers preserved) and produces a tagged object
with nested arrays, nested objects, negative numbers, booleans, and
quoted strings.

## Lint enforcement (deferred)

This RFC is parser-only. Future RFCs may add:

- **L046** — `@@locked` model edited without explicit human approval marker
- **L047** — namespace `@@boundary.exposes` includes a model that no longer exists
- **L048** — `@@compliance(tags: [...PII...])` on attribute without `@@example`
- **L049** — `@@example(expect: reject)` whose input *would* satisfy `@@inv`
  (consistency check between examples and invariants)

These are tracked separately so 1.6 stays a clean additive bump.

## Conformance

L3 implementations MUST:

1. Parse all eight constructs without rejecting the file.
2. Populate the corresponding IR fields with the values shown above.
3. Round-trip via `irToDsl` — `@@owner / @@status / @@adrRef / ...` re-parse
   into the same IR shape (best-effort: `irToDsl` may emit canonical key
   ordering and quote conventions).

Renderers MAY surface these fields as tooltips / overlays but are not
required to. Lint MAY emit informational diagnostics referencing them.
